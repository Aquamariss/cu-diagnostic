# Диагностика городского проекта

Лид-магнит курса [«Школа городских продюсеров»](https://cityuniversity.ru/school-urban-producers) (Городской университет 2.0).
Человек за 7–10 минут проходит опрос из 15 вопросов и сразу получает оценку проекта по методике С. Мурунова, сильные стороны, зоны роста, потенциал, ближайший шаг, роадмап на год и две CTA-кнопки.

## Запуск

```bash
npm install
cp .env.example .env   # заполнить ANTHROPIC_API_KEY и ADMIN_PASSWORD
npm start              # http://localhost:3000
npm test
```

Нужен Node.js 22.9+.

## Как это устроено

| Путь | Что там |
|---|---|
| `public/js/questions.js` | Вопросы, варианты ответов и баллы. Общий файл для браузера и сервера |
| `src/scoring.js` | Подсчёт баллов Q5–Q14 (максимум 17), интерпретация, выбор сильных сторон и зон роста, шаблонные тексты и роадмап |
| `src/ai.js` | Персонализация текстов через Claude API: правила методики собраны в системном промпте |
| `src/store.js` | Хранение заявок в `data/submissions.json` (временное решение до появления БД) |
| `server.js` | API, страница `/admin` и выгрузка CSV |
| `public/` | Интерфейс: стартовый экран, опрос, результат |

### Сценарий

1. **Старт.** Пользователь вводит ФИ, email и профиль (B2C/B2B, для информации) и даёт согласие на обработку ПД. Контакт сохраняется сразу, ещё до ответов.
2. **Опрос.** Один вопрос на экран, прогресс-бар, кнопка «Назад». Ответы хранятся в `localStorage`, поэтому после перезагрузки можно продолжить. Сервер запоминает номер вопроса, на котором человек остановился.
3. **Результат** показывается мгновенно: баллы и шаблонные тексты считает код по методике. Затем фоном выполняется запрос к Claude, и тексты сильных сторон, зон роста, потенциала, ближайшего шага и роадмапа заменяются персонализированными. ИИ не меняет баллы и выбор показателей. Если ключа нет или запрос не удался, остаётся шаблонная версия.
4. **CTA:** консультация и запись в ШГП. Клики учитываются в админке. Результат открывается по постоянной ссылке `/r/<id>` и сохраняется в PDF через печать.

### Правила методики, принятые в коде

- **Q7 (роль автора).** Функции разбиты на 4 части проекта: ценность и аудитория / люди и партнёры / ресурсы и город / результаты. 0 баллов, если отмечены только операционные функции. 1 балл, если есть хотя бы одна функция развития. 2 балла, если охвачены 3 и более частей и не отмечено «всё делаю сам». *Временное правило, будет пересмотрено.*
- **Зоны роста.** Сначала наименьший балл, без нормализации к максимуму. При равенстве первыми идут показатели, связанные с запросом Q15, затем порядок по стадии Q1.
- **Сильные стороны.** Только показатели с максимальным баллом, до 3 штук, порядок зависит от стадии Q1.
- **Ближайший шаг.** Если запрос Q15 совпадает с одной из зон роста, шаг строится на нём. Иначе шаг строится на самой базовой зоне роста, а запрос упоминается.
- **Q13.** Вариант «нет ресурсов» исключает остальные. **Q3, Q2:** при «Другое» появляется текстовое поле.

## Администрирование

`/admin` защищена HTTP Basic: логин любой, пароль из `ADMIN_PASSWORD`. На странице таблица заявок (ФИ, email, профиль, статус, стадия, формат, баллы, запрос, клики по CTA, ссылка на результат) и кнопка «Скачать CSV» со всеми ответами и UTM-метками.

> Данные лежат в JSON-файле на диске сервера. На хостингах с эфемерной файловой системой (Vercel, Heroku) они пропадут при перезапуске. Нужен сервер с постоянным диском, а позже база данных.
